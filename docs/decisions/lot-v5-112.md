# Lot v5.112 — Se connecter : temporaire ou permanente, l'appareil connecté (A651-A652)

> Maquette validée par l'auteur sur le canevas « Poste partagé — connexion par le téléphone »
> (page « Parcours retenu »), après une dizaine d'itérations commentées. Les formes écartées sont
> sur la page « Explorations » du même canevas.

## A651 — La connexion temporaire par e-mail (v5.112.0)

**Le besoin.** Sur un appareil du service, sans appareil connecté sous la main (téléphone resté au
vestiaire, batterie à plat), la seule voie était le code e-mail — qui ouvrait une connexion
DURABLE : exactement ce qu'on ne veut pas sur un poste partagé. L'auteur demande qu'on puisse
choisir « temporaire » aussi par e-mail.

**La décision.** Dans la carte « Se connecter », Temporaire › « Par e-mail » : l'adresse, le code,
puis l'heure de fin de garde (`linkEndChoices`, les mêmes repères que l'appareil connecté) et
« Se connecter jusqu'à 19:30 ». Après la vérification du code, la session TOUTE FRAÎCHE se déclare
poste partagé par `link_self(p_key_hash, p_label, p_ends_at)` (schema.sql § 10) : une ligne
`device_links` `claimed`, liée à la session courante (`session_id` du jeton), avec l'empreinte de la
clé du poste. À partir de là, rien ne la distingue d'un poste connecté par le code à viser : elle a
les limites d'A647 (`link_is_poste`), apparaît dans « Appareils connectés », se prolonge et se
déconnecte à distance, s'arrête à l'heure de fin (purge), dépose ses sessions.

**Pourquoi c'est sûr.** `link_self` ne peut que RESTREINDRE la session qui l'appelle : elle n'en
crée aucune, n'en lie aucune autre, et refuse une session déjà poste (une seule fois), un compte
non validé, une heure de fin hors de 30 min - 28 h, un sixième appareil actif ; le libellé est la
même grammaire fermée que `link_open`. Refusée, la connexion ne RESTE PAS ouverte : le client se
déconnecte (`Auth.signOut`, portée locale) et le dit — on avait choisi « Temporaire ».

**Limite dite.** Lire l'e-mail sur l'appareil du service y laisserait une messagerie ouverte :
l'écran dit « Lisez l'e-mail sur un appareil à vous, pas sur celui-ci ».

**Garde-fous.** `rls-tests.sql` 16.16 (heure de fin hors bornes, clé qui n'est pas une empreinte,
déclaration unique, limites de poste ensuite, libellé fermé — vu capable d'échouer : borne portée
à 48 h → rouge) ; `audit-lier.mjs` section 4 (le parcours complet, et le refus qui ne laisse pas de
connexion durable).

## A652 — La carte « Se connecter », le code dans la page, « appareil connecté » (v5.112.0, amende A643)

**Le constat (maquette, commentaires de l'auteur).** La connexion par le téléphone et la connexion
par e-mail étaient deux cartes concurrentes, sans dire ce qui les distingue ; « le téléphone » était
faux comme rôle (un compte de confiance peut être sur une tablette ou un ordinateur, et l'appareil
temporaire peut être un téléphone) ; le code s'ouvrait dans une fenêtre par-dessus ; le poste
connecté avait deux sorties (« Se déconnecter » et « Se déconnecter et effacer ») ; la bande de
l'accueil était bleue alors que rien ne demande d'action.

**La décision.**
- **Une carte « Se connecter »** (« facultatif », une ligne : sans compte, l'app fonctionne sur cet
  appareil) et DEUX CHOIX : ⏱ Temporaire « jusqu'à la fin de la garde, puis tout s'efface » ·
  ∞ Permanente « vous restez connecté ». **Rien n'est choisi d'office**, ni au bureau ni au
  téléphone (« y a le choix, n'essaie pas de deviner »). Temporaire : deux onglets, « Avec un
  appareil connecté » (le code à viser) · « Par e-mail » (A651). Permanente : le code e-mail. En
  pied de carte : « Pas encore de compte ? » › Créer un compte (le même code e-mail le crée).
- **Le code à viser s'affiche DANS la page** (`Link.inline`), plus dans `#linkModal` (qui reste pour
  le déverrouillage et la confirmation d'une suppression). Il se renouvelle seul à son expiration,
  **5 fois au plus**, puis « Le code s'est arrêté » + « Afficher un nouveau code » : une page
  oubliée ouverte ne crée pas de demandes indéfiniment. Ni renouvellement ni sondage onglet caché ;
  arrêt dès que la carte quitte l'écran (`Link.stopInline`).
- **Vocabulaire** : « un appareil où vous êtes connecté » connecte « cet appareil », temporairement
  (« Connecter un appareil », « Déverrouiller avec un appareil connecté », « Confirmer avec un
  appareil connecté », « Pas sur un appareil temporaire »). Le bouton de l'approbation dit la
  durée : « ⏱ Connecter jusqu'à 19:30 ».
- **Le poste connecté** : la carte du compte EST la carte du poste (« ⏱ Connexion temporaire »,
  l'heure de fin en grand, « puis tout s'efface de cet appareil », UNE sortie) ; la **bande** de
  l'accueil est neutre, ambre à 30 min de la fin (règle 8), et porte « Déverrouiller » quand
  l'édition est verrouillée.

**Formes écartées** (page « Explorations » du canevas) : deux cartes jumelles côte à côte
(« le côte à côte pas ouf ») ; la question « Qui utilisera cet écran après vous ? » en liste
dépliable ; une case « Appareil partagé » qui faisait disparaître le champ e-mail (« ça fait
bizarre ») ; un sélecteur segmenté sans valeur (paraissait désactivé) ; l'explication DANS le
sélecteur (« pas très joli ») ; taper son e-mail sur le poste pour recevoir une demande sur ses
appareils (« pas ouf niveau sécurité » : n'importe qui déclenche des demandes, et le nombre à
choisir parmi trois deviendrait un pari à une chance sur trois) ; choisir d'office selon le
pointeur (« n'essaie pas de deviner »).

**Garde-fous.** `audit-lier.mjs` : rien n'est choisi d'office et aucun code n'est demandé avant le
choix ; le code s'affiche dans la page sans fenêtre, avec son compte à rebours de renouvellement ;
la bande est sans couleur ; l'onglet « Par e-mail » arrête le code à viser.

## A653 — Le compte se charge : l'accueil ne se dit pas « vide » pendant le premier tirage (v5.112.1)

**Le constat (signalé).** À la connexion d'un compte sur un appareil neuf, l'accueil restait vide le temps
du premier tirage : « Votre bibliothèque est vide », l'invitation « Besoin d'exemples ? » — faux, et
alarmant pour qui sait avoir des aides dans son compte.

**La décision.** Tant que la PREMIÈRE synchro de la page n'a pas fini ET que ce compte n'a jamais rien
tiré sur cet appareil (aucun curseur d'aides ni de protocoles), l'accueil montre « Chargement de votre
compte… » (`role=status`) au-dessus de trois rangées qui respirent ; l'invitation aux exemples attend. À
la fin de la synchro — réussie ou non —, le vrai état revient. Un compte déjà synchronisé, ou hors ligne,
montre sa liste tout de suite : l'animation ne masque jamais du contenu présent. Plafond : 20 s après le
chargement de la page, jamais un chargement sans fin.

**Mouvement.** L'opacité (rangées) et le `transform` (anneau) seuls (`check-anim`) ; rien ne bouge sous
`prefers-reduced-motion: reduce`. L'accueil seul : jamais en mode crise (règle 11).

**Garde-fous.** `audit-doctrine.mjs`, section « Accueil · A653 » (tirage retenu au réseau : pendant /
après ; mouvement réduit) — vue capable d'échouer.
