# Lot v5.132 — Des images côte à côte : la grille d'images (A755)

**Origine.** L'auteur, capture d'une page Notion (« Echographie 4 points » : trois colonnes Fémoral · Normal ·
Thrombus, puis Poplité · Normal · Thrombus) : « comment faire cet alignement dans mes protocoles ? » ; puis, l'export
Markdown de Notion à l'appui : « ce qui va être tendu, c'est de comprendre que ces images sont côte à côte et pas les
unes à la suite des autres — Notion ne fait pas la distinction ». Arbitrage : « oui, fais la grille ». Aucun
changement de modèle ni de serveur : la grille est un TABLEAU du mini-Markdown.

## A755 — Une image seule dans une case est une vignette ; « Mettre en grille » construit le tableau

*Amende la ligne d'A607 « les colonnes Notion n'ont pas d'équivalent ».*

**Le constat.** L'export Markdown de Notion déroule les colonnes : « Fémoral / image / Normal / image / … ». Rien n'y
distingue six images côte à côte (3 × 2) de six images à la suite (1 × 6, 2 × 3) — toute détection AUTOMATIQUE se
tromperait un jour. Donc : l'app RENDRE une grille, l'AUTEUR dit combien de colonnes.

**Rendu.** Dans une case de tableau, un segment (entre deux `<br>`) qui n'est QU'une image `![…](img:ID)` devient une
vignette (`.md-fig.md-cfig` : la figure de lecture, un toucher l'agrandit) ; le reste reste du texte. Le tableau qui
porte une image (`md-tbl-img`) a des colonnes ÉGALES (`table-layout:fixed`) et tient dans la largeur — au téléphone,
trois colonnes d'environ 110 px plutôt qu'un défilement de côté (le `min-width` des tableaux de texte ne s'y applique
pas) — sans filets, comme Notion. La forme écrite : un tableau sans ligne d'en-tête (A609), une case par image,
`libellé<br>![…](img:ID)` — c'est du Markdown ordinaire (GitHub rend de même une image dans un tableau).

**« Mettre en grille »** (`mdGrille`, PURE, `?__actest`) : un passage « libellé, puis son image », répété, devient ce
tableau à 2, 3 ou 4 colonnes (conseillé : 3 si le compte s'y prête, sinon 2 — `mdGrilleN`). Le libellé = le texte
entre l'image précédente et la sienne (pour la première : la seule ligne juste au-dessus) ; le texte d'avant la
première et d'après la dernière reste autour — rien ne se perd ; un `|` du libellé s'écrit `\|`. Deux portes :
- **mise en forme en direct** : sélectionner les blocs (Ctrl/⌘ + clic, ou le mode sélection) → « Mettre en grille »
  dans la barre de sélection (présent dès deux images dans des blocs qui se suivent) → le nombre de colonnes ;
- **mode texte** : sélectionner le passage → « ＋ Insérer › Grille d'images » → le nombre de colonnes.
Le choix des colonnes est un menu sous son déclencheur (déroulant flottant au bureau, feuille au téléphone).

**Couplages tenus.** Une image dans une case compte comme UTILISÉE (`mdImgIds`) — sans quoi le ménage de sortie
(`leaveGC`) l'aurait retirée en quittant l'éditeur ; « Retirer » une image vide aussi ses cases ; « Aller au
passage » la trouve dans un tableau (`miHas`) ; l'export « sans les fichiers joints » (A751) vide aussi les cases.
L'aide-mémoire de syntaxe le dit.

**Non fait, à dessein.** Aucune suggestion automatique à l'import Markdown (elle devinerait) : c'est l'import de
l'export HTML de Notion (lot suivant) qui retrouvera les colonnes, parce que l'HTML les garde.

**Témoins.** `tests.html` (passage → tableau exact, moins de deux images, `|` échappé, colonnes conseillées, rendu à
quatre vignettes, images des cases utilisées, export léger) ; `audit-doctrine` « A755 » (en direct : Ctrl+clic sur
les blocs, « Mettre en grille », 3 colonnes ; en mode texte : « Insérer › Grille d'images », 2 colonnes ; au
téléphone, la grille tient dans la largeur) — vérifié capable d'échouer (porte, menu et largeur neutralisés → trois
rouges).

*Formes écartées.* Des images à la suite rendues côte à côte d'office : changerait l'affichage des protocoles
existants sans que leurs auteurs l'aient choisi. Une détection automatique à l'import Markdown : rien ne la fonde.
