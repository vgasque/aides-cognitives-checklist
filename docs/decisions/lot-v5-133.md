# Lot v5.133 — Importer l'export HTML de Notion (A756)

**Origine.** L'auteur : « fais la grille, et l'import HTML de Notion (en plus du Markdown) » — l'export Markdown de
Notion ne garde pas les colonnes (A755), l'export HTML les garde. Aucun changement de modèle ni de serveur.

## A756 — Une page .html de Notion (seule, ou dans le .zip) entre comme une page .md ; ses colonnes deviennent une grille

*Complète A562 (import Notion), A633 (verser une page dans le protocole ouvert) et A755 (la grille).*

**Par les mêmes portes.** « Importer un fichier », le dépôt, et « Page Notion » de l'éditeur (A633) acceptent aussi
une page `.html` seule et les pages `.html` d'un `.zip` (`dataKind` → `'html'` sur `<!DOCTYPE html` ou `<html` en
tête ; `UP_KINDS.data` l'annonce). Un export emballé dans un second `.zip` est déballé comme avant. Même suite :
l'atelier d'import, un protocole en brouillon par page.

**Lecture.** `notionHtml(doc, dir, ids)` (PURE hors `DOMParser`, `?__actest`) lit le document parsé par `DOMParser`
— jamais inséré dans la page : rien n'y est exécuté (un `<script>` est ignoré) ni chargé — et n'en tire que du TEXTE
au format du mini-Markdown, qui passe ensuite par `migrateProtocol` et `mdRender` comme toute importation (règles 4
et 5). Profondeur bornée (40). Correspondances :
- titres `h1`–`h3` → `#`–`###` (au-delà : `###`) ; titre repliable (`details` dont le `summary` est en 1,5 em ou plus)
  → titre du même rang, qui se replie dans l'app (A171) ; repliable simple → paragraphe en **gras** suivi de son contenu ;
- paragraphes ; gras, italique, souligné (→ gras, comme l'import Markdown), surligné, barré, `code` ; liens `https`
  gardés, tout autre lien (une page de l'export, `javascript:`) réduit à son texte ;
- listes à puces et numérotées imbriquées (2 espaces par niveau, A607), cases à cocher (`- [ ]`, `- [x]`) ;
- tableau simple (en-tête si `thead` ou `th`, sinon en-tête vide, A609 ; `|` protégé) ; encadré (`callout`) et
  citation → `> … ` ; séparateur ; bloc de code ;
- image (`figure`/`img`) → `![légende](img:ID)` par les mêmes chemins (`notionPath`) et la même légende tue
  (`notionCap`) que l'import Markdown ; absente de l'archive → NOMMÉE dans le texte (« *[Image absente de l'archive :
  …]* ») ; vidéo → nommée (« *[Vidéo non importée : …]* ») et comptée au message de fin, tant que l'app ne lit pas
  les vidéos ;
- **colonnes** (`div.column-list > div.column`) : chaque colonne se découpe en unités « libellé(s) + image » ; une
  rangée de colonnes devient une grille d'A755 (une case par unité, `libellé<br>![…](img:ID)`) ; deux rangées de
  colonnes qui SE SUIVENT, de même largeur, forment UNE grille (la page de l'auteur : Fémoral · Normal · Thrombus,
  puis Poplité · Normal · Thrombus). Une colonne qui porte autre chose (liste, tableau…) ou une rangée sans image :
  les colonnes sont lues l'une après l'autre, comme l'export Markdown — rien ne se perd.

**Ce qui n'est pas vérifié sur un vrai export.** La structure lue (`page-title`, `page-body`, `column-list`/`column`,
`figure.image`, `figure.callout`, `details`/`summary`, `to-do-list`, `simple-table`) est celle des exports HTML de
Notion connue à ce jour ; elle est éprouvée sur un fixture qui la reproduit, pas sur un export réel. Un élément
inconnu est parcouru (son texte reste) ; à relire sur la première page importée.

**Témoins.** `tests.html` (fixture de la page de l'auteur : chemins décodés, titre, titre repliable, gras, deux rangées
de colonnes → UNE grille, image absente et vidéo comptées, listes, case, tableau à « | », encadré, lien
`javascript:` réduit et `<script>` ni exécuté ni recopié, `dataKind`) ; `audit-doctrine` « Import · A756 » (un .zip
HTML par `readImportFile` : un protocole, six images rangées, UNE grille de trois colonnes) — vérifié capable
d'échouer (fusion des rangées neutralisée → rouge).
